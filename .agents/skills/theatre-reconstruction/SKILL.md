# 剧场室内三维重建

交付可追溯资料的室内模型、可选择的独立座位和对应眼点；默认范围为主剧场观众厅与可见舞台。先读仓库 `AGENTS.md` 和 `README.md`，以下路径均相对仓库根目录。

## 资料搜集与可信度

- 核对城市、剧院名称及别名、具体厅型和资料年代，避免混入同名剧院、音乐厅或小剧场。组合中英文名称与“平面 / 剖面 / 座位图 / CAD / PDF / auditorium / plan / section / seating chart”检索。
- 优先查剧院及运营方、设计院和建筑师，其次查有作者署名的建筑媒体与演出资料。打开原始页面，检查图纸图例、比例尺、楼层和发布日期，搜索缩略图只用于定位来源。
- 用平面确定分区、通道和轮廓，用剖面确定台口、坡度、层高与楼座叠合，用分层座位图确定逐排数量与包厢，用舞台望向观众席和观众席望向舞台的照片核对外观。
- 每份有效资料记录 URL、发布者、日期/版本、厅型、用途和署名；可留存的参考图放入 `public/reference/<venue-id>/`。资料冲突时保留差异及选用理由，不把不同年代的容量拼成同一配置。
- 分清有来源的事实、据图推算和建模假设。缺少尺寸时先交付标明估算的原型；若目标要求实测精度，明确还需哪些 CAD、剖面、高程或现场数据。不要为凑官方总容量增删座位。

## 从二维座位图到三维空间

1. 整理楼层、区域、逐排座数、通道、包厢及可变乐池配置。有清晰逐座符号时描取中心并输出叠加图复核漏点、重复点和分块；只有逐排数量时按分块重建，明确其坐标为插值估算。
2. 保留二维定位与来源语义：`mapPosition`、`topology`、`confidence`；不得把推算位置标成原图描点。未核实票务对应关系时保持 `ticketIdentityVerified=false`，重建编号与票面座号分开说明。
3. 统一为米、Y 轴向上、台口地面中心为原点、观众厅位于 +Z。用已知尺寸校准平面和剖面；二维座位图可能是展开图，不能直接当作带比例的建筑平面。单张照片不能唯一确定真实尺寸。
4. 先建立台口、地坪、逐排踏步、楼座和包厢，再添加栏板、墙体、顶棚、材质及比例人物。座椅和地坪共用高程/曲面函数，避免两套计算造成悬空或穿插。各剧场保持独立布局与建筑，不套用另一剧场的轮廓。
5. 每个位置保留稳定 `seatId`、楼层/区域/排/座、`position`、`yaw`、`eyeOffset`。复用项目座椅实例化与按材质合并的建筑绘制；导出保留座位标识。总览中的建筑隐藏不能改变实际遮挡判断或遗漏导出几何。

## 视角与项目接入

- 通过 `src/venues.js` 注册独立布局、建筑、参考图、来源说明和默认座位，复用现有选座、相机与导出流程。
- 从座位地坪、坐姿眼高和座椅朝向计算眼点。选座后相机固定眼点，拖动仅转头；总览保留独立缩放。沿用本项目的眼高 1.16 m、垂直 FOV 75°、`zoom=1` 默认值，并明确它们是显示预设，不能宣称为实测人眼校准。
- 切馆同步更新座位图、资料、精度说明、URL 和导出内容；资源使用相对路径以支持 GitHub Pages 子目录。

## 验收与交付

- 运行 `npm run build`、`npm test`。新增模型检查分层/分区/逐排数量、唯一编号、有限且唯一的眼点、座椅间距、全部地坪支撑和乐池显隐恢复，保留已有剧场回归。
- 按当前任务授权执行浏览器验收：实际点击二维/三维座位，检查楼层、侧区、包厢与前后排；验证转头不漂移、默认视野、总览返回、乐池、手机布局和 URL 定位。用多处相同朝向的实景对照核对形态与遮挡，不以一张好看的截图代替验证。
- 复用 `window.__THEATRE_VIEW__` 的 `inspectAllSeatCameras()`、分批 `inspectFloorSupport()` 和 `inspectStageVisibility(ids)`；舞台中心投影通过只说明相机朝向正确，不能证明舞台无遮挡。
- 从实际应用导出座位 JSON 和 GLB，核对数量、标识、单位及当前配置；截图使用实际渲染结果。资料与说明随模型维护，模型/坐标放 `artifacts/`，测试与精度边界放 `acceptance/` 或验收报告。
- 分别报告“交互与几何内部一致性”和“真实建筑精度”。没有现场校准、官方座号和遮挡资料时，不宣称实测选座或购票视线已验证。提交、发布和浏览器操作遵循当前授权，skill 本身不增加权限。
